# aioslsk: browse/download, search, and basic chat improvements

_Revision: gaps removed; downloading kept strictly backward compatible; chat
scoped down to the basic Soulseek UX._

## Context

`aioslsk` is an async Soulseek protocol client. It already implements the wire
protocol for browsing, transfers, search, and chat, but its high-level API is
thin in three areas, benchmarked against the `slskd` wiki spec
(`/home/tigor/projects/_forked/slskd/wiki/`):

- **Browse/download user files** — only low-level two-step commands exist; no
  navigable share tree, no directory/batch download, no decoded audio metadata.
- **Search** — no per-search options (timeout/limits), no client-side result
  filtering (`minbr`/`islossless`/…), no completion event/awaitable.
- **Chat** — private messaging is stateless (no conversation/history, no in/out
  direction); rooms retain users/tickers but no message scrollback.

**Goal:** add ergonomic capabilities in all three areas as **purely additive**
changes. No existing command, event, manager method, model field, or setting is
renamed, removed, or behavior-changed.

**Design rules (this revision):**
1. **No gaps** — every new symbol has a concrete home and dependency; no
   "resolve at implementation time" hand-waving (notably: outbound message id,
   directory-download method placement, send path).
2. **Downloading stays strictly backward compatible** — the existing
   `TransferManager.download()`, `add()`, `queue()`, the `Transfer` model and
   its state machine are **untouched**. New download capability is additive only.
3. **Basic chat only** — match the basic Soulseek desktop UX: per-user
   conversation scrollback (in + out) and per-room scrollback. **No** read/unread
   tracking, ack/receipts, typing, conversation open/close state, or multi-event
   machinery. Opt-in, default OFF.

## Area 1 — Browse / download user files

### 1a. Decoded file-attribute view (foundation)
File: `src/aioslsk/protocol/primitives.py` (next to `FileData`/`AttributeKey`).

```python
@dataclass(frozen=True, slots=True)
class FileAttributes:
    bit_rate: Optional[int] = None       # AttributeKey.BITRATE (kbps)
    duration: Optional[int] = None       # AttributeKey.DURATION (seconds)
    is_vbr: Optional[bool] = None        # AttributeKey.VBR (None == unknown, not CBR)
    sample_rate: Optional[int] = None    # AttributeKey.SAMPLE_RATE (Hz)
    bit_depth: Optional[int] = None      # AttributeKey.BIT_DEPTH

    @property
    def length(self) -> Optional[int]: ...        # alias for duration
    @property
    def is_lossless(self) -> bool: ...            # sample_rate and bit_depth present
    @property
    def is_lossy(self) -> bool: ...               # bit_rate present and not lossless
    @classmethod
    def from_file_data(cls, file: 'FileData') -> 'FileAttributes': ...
```
- **Reuse** `FileData.get_attribute_map()` (primitives.py:545) and `AttributeKey`.
- Add additive accessor `FileData.decode_attributes() -> FileAttributes` (a new
  method on the existing class; no field/signature change, no wire-format change).

### 1b. Navigable browse tree + high-level command
New file `src/aioslsk/browse.py` (imports only `primitives` + `constants`, so no
import cycle):

```python
@dataclass(slots=True)
class BrowseDirectory:
    name: str                            # full backslash remote path
    files: list[FileData] = field(default_factory=list)
    subdirectories: dict[str, 'BrowseDirectory'] = field(default_factory=dict)
    is_locked: bool = False
    def get_path(self, path: str) -> Optional['BrowseDirectory']: ...
    def walk(self) -> Iterator['BrowseDirectory']: ...      # self + descendants
    def all_files(self) -> Iterator[FileData]: ...          # files in self + descendants

@dataclass(slots=True)
class BrowseResult:
    username: str
    root: BrowseDirectory                # synthetic root, name=""
    visible: list[DirectoryData]         # raw passthrough (lossless)
    locked: list[DirectoryData]
    @classmethod
    def from_shares_reply(cls, username, reply: SharesReply) -> 'BrowseResult': ...
    def get_directory(self, path: str) -> Optional[BrowseDirectory]: ...
    def iter_files(self, include_locked: bool = True) -> Iterator[FileData]: ...
```
- The shares reply is a **flat** `list[DirectoryData]` whose `name` is the full
  backslash path; `from_shares_reply` splits names on `PATH_SEPERATOR_PATTERN`
  (constants.py:25), nests into `subdirectories`, and flags `is_locked` for
  entries from the locked list. Keeps the raw `visible`/`locked` lists so nothing
  is lost vs. the low-level command.

New command in `src/aioslsk/commands.py`, a near-clone of `PeerGetSharesCommand`
(commands.py:905) differing only in `handle_response`:
```python
class PeerBrowseCommand(BaseCommand[PeerSharesReply.Request, BrowseResult]):
    # __init__, send, build_expected_response: identical to PeerGetSharesCommand
    def handle_response(self, client, response) -> BrowseResult:
        return BrowseResult.from_shares_reply(
            self.username, (response.directories, response.locked_directories or []))
```
Convenience method on the **client facade** (where `execute()` lives, so no
manager has to reimplement the response-future plumbing):
```python
# SoulSeekClient
async def browse_user(self, username: str) -> BrowseResult:
    return await self.execute(PeerBrowseCommand(username), response=True)
```
`PeerGetSharesCommand` / `PeerGetDirectoryContentCommand` / `UserSharesReplyEvent`
/ `UserDirectoryEvent` are all untouched.

### 1c. Directory + batch download (additive only — no change to existing download)
**Backward-compat guarantee:** `download(username, filename, paused=False)`,
`add()`, `queue()`, `abort()`, `pause()`, `remove()`, and the `Transfer`
model/state machine are **not modified**. The two new methods are pure wrappers.

One new manager method (matches `transfers.download(...)`), and one new facade
method — **no name collision, no overload ambiguity** (this removes the previous
"two `download_directory` methods" gap):

```python
# TransferManager  (src/aioslsk/transfer/manager.py)
async def download_many(self, username: str, filenames: Iterable[str],
                        paused: bool = False) -> list[Transfer]:
    """Enqueue many files for one user. Wraps download() per file; per-file
    try/except + logger; continues on failure; returns the created Transfers.
    Dedup is free — add() already returns the existing Transfer on a match."""
```
```python
# SoulSeekClient facade  (src/aioslsk/client.py)
async def download_directory(self, username: str, directory: str,
                             recursive: bool = True, include_locked: bool = False,
                             paused: bool = False) -> list[Transfer]:
    """Browse the user (PeerBrowseCommand) and enqueue every file under
    `directory` via transfers.download_many(). recursive -> all_files(), else the
    directory's own files. Raises ValueError if `directory` is not in the tree."""
```
- Directory download lives at the facade because it needs to browse (a
  request/response that uses `execute`); `TransferManager` stays free of
  command/`execute` plumbing. Callers who already hold a `BrowseDirectory` skip
  the browse and call `transfers.download_many(user, [f.filename for f in node.all_files()])`.
- Path semantics: `file.filename` (remote backslash path) is passed straight to
  `download()`, exactly as search-result downloads already work — **no path
  transformation**, so download behavior is identical to today.

## Area 2 — Search improvements

### 2a. Per-search options + completion
File: `src/aioslsk/search/model.py`:
```python
@dataclass(slots=True)
class SearchOptions:
    timeout: Optional[float] = None          # idle/inactivity seconds; None -> setting
    response_limit: Optional[int] = None
    file_limit: Optional[int] = None
    min_response_file_count: int = 0
    max_peer_queue_length: Optional[int] = None
    min_peer_upload_speed: int = 0
    store_results: Optional[bool] = None      # override settings default

class SearchCompletionReason(Enum):
    TIMED_OUT
    RESPONSE_LIMIT_REACHED
    FILE_LIMIT_REACHED
    CANCELLED
```
Additive **trailing, defaulted** fields on `SearchRequest` (slots dataclass; the
positional `SearchRequest(ticket, query, ...)` construction in `_wishlist_job`
keeps working): `options`, `complete: bool = False`, `completion_reason`,
`file_count: int = 0`, and a private
`_complete_future: Optional[asyncio.Future] = field(default=None, repr=False, compare=False)`.
Plus:
```python
async def wait_for_completion(self, timeout=None) -> SearchCompletionReason:
    """Lazily create _complete_future on the running loop, then await it."""
```

File: `src/aioslsk/search/manager.py` — **keyword-only** `options` param on
`search`/`search_room`/`search_user` (existing positional signatures unchanged):
```python
async def search(self, query: str, *, options: Optional[SearchOptions] = None) -> SearchRequest
```
- New `_complete_search_request(request, reason)`: idempotent (guard on
  `request.complete`); cancels the timer; sets completion fields; resolves
  `_complete_future` if present; emits the new `SearchRequestCompleteEvent`; then
  pops `self.requests` and emits the existing `SearchRequestRemovedEvent` (so
  current listeners keep working — completion is a superset of today's
  timeout-removal).
- In `_on_peer_search_reply` (manager.py:380), **only when `request.options` is
  set**: apply the response-level acceptance gate
  (`min_response_file_count`/`max_peer_queue_length`/`min_peer_upload_speed`)
  before storing/emitting; bump `file_count`; complete on response/file limit;
  and reschedule the idle timer via `Timer.reschedule()` (tasks.py:103).
- **Backward compat:** when `options is None`, the existing
  `_attach_request_timer_and_emit` / `_timeout_search_request` path is used
  unchanged — byte-for-byte current behavior, no new event fires.

New event in `src/aioslsk/events.py`:
```python
@dataclass(frozen=True, slots=True)
class SearchRequestCompleteEvent(Event):
    query: SearchRequest
    reason: SearchCompletionReason
```

### 2b. Client-side result filtering
File: `src/aioslsk/search/model.py` (near `SearchQuery`) — stateless, caller-side,
composes with `FileAttributes`:
```python
@dataclass(slots=True)
class SearchFilter:
    include_terms: list[str]; exclude_terms: list[str]
    min_bit_rate / min_bit_depth / min_file_size / min_length /
        min_files_in_folder: Optional[int]
    is_vbr / is_cbr / is_lossless / is_lossy: Optional[bool]
    @classmethod
    def parse(cls, expr: str) -> 'SearchFilter': ...    # minbr/minbitrate, minbd, minfs,
                                                        # minlen, minfif, isvbr/iscbr,
                                                        # islossless/islossy, term, -term
    def matches_file(self, file: FileData) -> bool: ...
    def filter_result(self, result: SearchResult) -> SearchResult: ...   # NEW object
    def filter_results(self, results: Iterable[SearchResult]) -> list[SearchResult]: ...
```

- **Reuse** `FileAttributes` (1a), `create_term_pattern` (shares/utils.py:25),
  `PATH_SEPERATOR_PATTERN`. `min_files_in_folder` groups surviving files by parent

## Area 3 — Basic chat (opt-in, default OFF)

Scope = basic Soulseek UX: keep a **conversation scrollback** of incoming and
outgoing private messages per user, and optional **room scrollback**. Nothing
more.

### 3a. Settings
File: `src/aioslsk/settings.py` — minimal blocks, all default-off:
```python
class PrivateChatSettings(BaseModel):  store_history: bool = False;  max_messages: int = 1000
class RoomChatSettings(BaseModel):     store_history: bool = False;  max_messages: int = 1000
class ChatSettings(BaseModel):
    private: PrivateChatSettings = Field(default_factory=PrivateChatSettings)
    room: RoomChatSettings = Field(default_factory=RoomChatSettings)
# Settings: chat: ChatSettings = Field(default_factory=ChatSettings)
```
Existing settings files still load (everything defaulted).

### 3b. Models (new package, no change to `ChatMessage`)
New `src/aioslsk/chat/__init__.py`, `src/aioslsk/chat/model.py` — reuse the
`slots_params` 3.10-compat pattern verbatim from `room/model.py`:
```python
class MessageDirection(Enum):
    OUT = 0
    IN = 1

@dataclass(**slots_params)
class PrivateMessage:                 # NEW model; legacy ChatMessage untouched
    timestamp: int
    user: User                        # the remote party
    message: str
    direction: MessageDirection
    is_direct: bool = True            # reuse protocol semantics: False == replayed/offline

@dataclass(**slots_params)
class Conversation:
    username: str
    messages: list[PrivateMessage] = field(default_factory=list)
    last_activity: int = 0
```
- **No `id`** field → no outbound-id generator needed (this removes the previous
  "where does the outbound id come from" gap). No `is_read`, no `is_active`, no
  unread counters — out of basic scope.

### 3c. ChatManager (`client.chat`)
New `src/aioslsk/chat/manager.py` — `ChatManager(BaseManager)` built with
`(settings, event_bus, user_manager, network)` (same shape as `RoomManager`; no
client ref needed). API is deliberately small:
```python
@property
def conversations(self) -> dict[str, Conversation]
def get_conversation(self, username: str) -> Optional[Conversation]
def get_conversations(self) -> list[Conversation]
async def send_message(self, username: str, message: str) -> PrivateMessage
```
Behavior:
- **Inbound:** registers a listener on the existing `PrivateMessageEvent`
  (`UserManager` is not modified). When `chat.private.store_history` is on, derive
  a `PrivateMessage(direction=IN, is_direct=event.message.is_direct,
  user=event.message.user, ...)`, append to the conversation, emit
  `ConversationMessageAddedEvent`.
- **Outbound:** `send_message` sends via
  `network.send_server_messages(PrivateChatMessage.Request(username, message))`
  — the same protocol primitive `PrivateMessageCommand` uses (no logic
  duplicated; both are legitimate public send paths, `PrivateMessageCommand`
  stays untouched). Private messages get **no server echo**, so when history is
  on it appends an `OUT` `PrivateMessage` (user resolved via
  `user_manager.get_user_object(username)`) and emits
  `ConversationMessageAddedEvent`. Returns the `PrivateMessage` either way.
- **Default-off:** with `store_history=False`, the inbound listener returns early
  and `send_message` only sends (identical to using `PrivateMessageCommand`);
  `get_conversations()` returns `[]`. Current behavior fully preserved.
- Keyed by **exact** username string (Soulseek usernames are case-sensitive,
  matching `_users`/`_rooms`). Per-conversation cap via `max_messages` (trim
  oldest). Blocked users never emit `PrivateMessageEvent` (user/manager.py:319),
  so they are auto-excluded — no extra code. Clear `_conversations` on
  `ConnectionState.CLOSED` (matches `reset_users`/`reset_rooms`). `stop()` returns
  `[]` (no tasks).
- **Replay/dedup:** the existing handler auto-acks every PM immediately
  (user/manager.py:314) before any other processing, so the server does not
  replay — each message is delivered once. No dedup logic is required (this
  removes the previous "replay dedup" gap by relying on existing behavior).

### 3d. Wiring + event

### 3e. Room scrollback (opt-in, minimal)
- `src/aioslsk/room/model.py`: append one **trailing defaulted** field
  `Room.messages: list[RoomMessage] = field(default_factory=list)` (all `Room`
  constructions are keyword-only → slotted-dataclass-safe; `RoomMessage` is
  **not** modified).
- `src/aioslsk/room/manager.py`: in `_on_chat_room_message` (manager.py:142),
  gated by `chat.room.store_history`, append the `RoomMessage` to `room.messages`
  (cap via `max_messages`) and clear `room.messages` on join for "since join"

  captured. Blocked room messages already return early before append. No new
  event — UIs use the existing `RoomMessageEvent` plus `room.messages` for
  scrollback. (Own-vs-other rendering: compare `message.user.name` to
  `client.session.user.name` — no new field needed.)

## Backward-compatibility guarantees
- No existing symbol renamed/removed; no existing default behavior changed.
- **Downloading:** `download()`, `add()`, `queue()`, the `Transfer` model and
  state machine are untouched; new download paths are additive wrappers only.
- New `SearchRequest`/`Room` fields are defaulted and appended last.
- `options=None` search path is byte-for-byte identical to today.
- New chat manager + settings default-off; `client.chat` is inert until enabled;
  `ChatMessage` / `PrivateMessageEvent` / `PrivateMessageCommand` unchanged.

## Gaps closed vs. previous revision
1. **Outbound PM id** — eliminated by dropping `id` from the basic `PrivateMessage`
   model (no id generator needed).
2. **Duplicate `download_directory`** — single facade `download_directory(str)` +
   manager `download_many(filenames)`; no overloaded/duplicate method.
3. **PM send duplication** — `send_message` uses the `PrivateChatMessage.Request`
   primitive directly; `PrivateMessageCommand` is left untouched (no shared logic
   to drift).
4. **Replay dedup** — relies on the existing immediate auto-ack; no dedup code.
